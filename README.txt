花椒日历 · 安卓版 2.1
====================

2.1 改了什么（这一版）
--------------------
1. 新增「上课时间」：夏季 / 冬季两套作息表按学校那张表内置好了，逐节可改；
   第 3、4 节还能按教学楼分档——逸夫楼、教 6 栋、教 10 栋、图书馆比教 25 栋晚。
   改完立刻同步：上课提醒、导出的日历、统计页里的时间全都跟着变。
2. 学期统计重建：只读「一周」课表当模板，其余按周次表达式本地推算，
   点任意一周秒开；之前是逐周再拉 7 天数据，网一慢就整页空白。
3. 交互打磨：页面淡入上移、按钮按下回弹、读数据先出骨架屏 + 真实进度条。
4. 版本号 2.1（versionCode 7），可直接覆盖 2.0 安装。


2.0 改了什么
------------
底部导航中间那一栏，从「校历」换成了「拓展」，点进去是一个功能中心：
考试安排、月视图、学期统计、上课提醒、桌面小组件、导出日历，
原来的校历降为其中一个入口（教学日历），缩放能力一点没动。

1. 考试安排
   教务把考试当成普通课程条目下发，名字后面挂个 (考试)。
   所以做法很直接：把「第 1 周 → 最后一周」每一天的课表都捞一遍，
   筛出带考试标签的条目，按日期排好——已经考完的也留着，
   灰掉并标「已结束」，这样才是「本学期所有考试」。

   · 顶部大卡：最近一场没考的考试 + 天/时/分三格倒计时，每 20 秒自己走；
   · 下面列表：每条显示月/日、星期、时间、节次、地点，右侧「还有 X 天」；
     已考完的排在后面，用一条「已结束 N 场」的分隔线隔开；
   · 首次扫描约 20~40 秒（3 并发，一天一个请求，进度条实时走），
     结果缓存 12 小时；过期了先照旧显示、后台悄悄重扫；
   · 有天没取到会在提示里说明「X 天没取到，结果可能不全」，
     点右上角重新扫就行；
   · 时间是用「节次时间表」换算的——教务只给第几节，页面底部也写明了
     以教务处通知为准。

2. 月视图
   整月 6×7 网格，每格显示当天有几节课（最多三个点），有课的日子淡淡上色，
   今天描边高亮。点任意一格直接跳到那天的日视图（路由 #/calendar/日期）。
   数据缓存优先，翻月份才补请求，加载时图例那行会显示「已加载 X/Y 天」。

3. 学期统计
   主结构是「第 1 周 → 最后一周」的周列表，点某一周进去看那一周的课表。
   学生找东西的时候想的是「第 12 周我上什么」，不是「这门课上几次」，
   所以按周组织；全学期的汇总数字仍然保留在最上面。

   · 四张概览卡：课程门数 / 每周课时 / 全学期上课次数 / 涉及楼栋；
   · 按周查看：20 行，每行周次 + 日期范围，当前周蓝色高亮、已过的周淡化，
     点进去是该周详情；
   · 周详情：顶部一张卡（第几周、日期范围、几天有课/几节/几门课本周不上），
     下面按周一到周日分组，每条课显示节次、上下课时间、地点、教师；
   · 实现上只取「一周」的课表当模板（本周没课就自动试前后一周），
     剩下的按周次表达式本地推算，所以点任意一周都是秒开，不再逐周发请求；
     读不到时会给具体原因和「重新统计」按钮，不会只剩一片空白；
   · 楼栋分布：按次数排序的横向条形图，楼栋从「地点」里抠出来
     （教25栋-101 → 教25栋，逸夫楼301 → 逸夫楼，北区田径场 → 北区田径场）；
   · 每门课：一个紧凑列表，周几、第几节、共上几次；
   · 考试条目不参与统计（它不是课）。

4. 上课提醒（本地通知）
   JS 侧算好「未来 14 天每一个该提醒的时刻」，一次性交给原生排闹钟。

   · 提前时间：5/10/15/30 分钟快捷选项 + 自定义 0~120 分钟；
   · 「几点上课」交给「上课时间」页里的作息表（夏季/冬季 + 按楼栋分档）；
     那边改完回到本页会自动按新时间重排，本页底部也放了入口；
   · 原生用 AlarmManager.setExactAndAllowWhileIdle，Android 12+ 没给
     精确闹钟权限时自动降级成不精确闹钟（可能晚几分钟，但不会不响）；
   · 通知渠道 IMPORTANCE_HIGH，带声音震动，点通知打开 App；
   · 关机重启 / 覆盖安装后自动重排（计划存了一份在 SharedPreferences）；
   · 页面会检查通知权限和精确闹钟授权，缺哪个给哪个按钮，点一下跳系统页。

5. 桌面小组件（今日课程）
   4×2 的小卡片，标题「今日课程 + 日期」，下面最多 6 行：色条 + 时间 +
   课程名 + 地点，超过 6 节显示「还有 N 节…」，没课显示「今天没有课」。

   · 数据来源：网页侧把今天的课序列化成 JSON 推给原生，存在
     SharedPreferences，小组件只负责画，不联网不解析 HTML，所以很快；
   · 打开 App、刷新课表、切页面都会顺手推一次，桌面上不会停在旧数据；
   · 跨天保护：如果存的数据不是今天，宁可显示「打开花椒日历，同步今天的课」，
     也不会把昨天的课当成今天的摆在桌面上；
   · 深浅色跟着 App 的主题走；
   · 「添加到桌面」用的是 Android 8+ 的 requestPinAppWidget，会弹系统确认框；
     部分国产桌面不支持这个 API，页面里写了手动添加的路径。

6. 导出 .ics 到系统日历
   把整学期课表展开成一条条日程，交给系统日历导入。

   · 为什么不用 RRULE：教务的周次是「1-8,10-17」这种带断档的表达式，
     还夹着单双周，用 RRULE 拼很脆；直接按周展开成一个个 VEVENT，
     单双周、跳周都不会算错。一学期十几门课约 90 条事件、28 KB；
   · 进页面就开始读本周课表，顶部直接显示「已读取 N 个上课时段 ·
     第 N 周 · 10/26 - 11/1」，点按钮立刻出结果，不用干等；
   · 某一周一条课都没取到（放假、教务对某些日期返回空、或者请求全失败），
     会自动再试上一周和下一周——课表按周重复，换上哪一周都不影响导出结果；
   · 真取不到时不会只说一句「没有拉到课程」，而是分情况告诉你：
     凭证失效 → 直接跳去重新绑定；连不上教务 → 显示教务返回的错误；
     这周确实没课 → 明说「这一周没有课」；
   · 每行严格按 75 字节折行（中文一个字 3 字节，按字符折会超标）；
   · 可选 0/5/15/30 分钟前提醒，写进 VALARM，导入后系统日历自己会弹；
   · 落地：先写应用专属目录，再复制一份到「下载」（Android 10+），
     然后用自建 ContentProvider 以 content:// 授权给系统日历打开；
     没有能直接吃 text/calendar 的应用时，退到分享面板；
   · 重复导入会产生重复日程，页面里也提醒了先删旧的再导。


7. 上课时间（2.1 新增）
   教务只下发「第几节」，所以「第 N 节几点上」必须由本地换算。这张表就是基准。

   · 两套作息都内置：冬季（11/1 起）和夏季（5/6 起），每年自动切换；
     也可以手动钉死其中一套（出门在外、临时调课都能用）；
   · 每节都能改开始/结束时刻，改完写本地、立即重排闹钟；
   · 第 3、4 节按教学楼分档，和学校作息表一致：
       冬季  教25栋 / 教31栋2、3层 / 其它    10:05-10:50、10:55-11:40
             逸夫楼 · 教38栋 · 教31栋4-6层   10:10-10:55、11:05-11:50
             教6栋 · 教10栋 · 图书馆          10:20-11:05、11:15-12:00
       夏季  教25栋 / 教31栋2、3层 / 其它    10:05-10:50、10:55-11:40
             逸夫楼 · 教6栋 · 教10栋 · 图书馆  10:20-11:05、11:15-12:00
     换算时按课程「地点」自动选档，教31栋再看楼层（4、5、6 层走晚的那档）；
   · 夏季和冬季的下午整体差半小时（14:00 vs 14:30），这是最容易被忽略的地方；
   · 「恢复学校默认时间」一键回到内置表。

几个会碰到的实际问题
--------------------
· 提醒不响？
  九个里面八个是电池优化。国产系统（MIUI / ColorOS / OriginOS…）
  会把后台应用冻结，闹钟被推迟或吞掉。到「设置 → 应用 → 花椒日历 →
  省电策略」改成「无限制」，并把「自启动」打开。
  另外 Android 13+ 的通知权限、Android 12+ 的精确闹钟权限，
  提醒页顶部会直接告诉你缺哪个。

· 小组件加不上？
  部分桌面不支持系统的 requestPinAppWidget，长按桌面空白处 →
  小组件 → 找「花椒日历」手动拖出来。

· 考试扫得慢？
  它真的在一天一天问教务。第一次十几秒是正常的，之后走缓存秒开。
  学期末考试多的时候，扫出来十几场很正常。

· 导出的日历时间不对？
  去「上课提醒 → 节次时间」把 12 节开始时间改成你们学校的作息，
  再导一次。这张表是提醒和导出的唯一时间来源。

关于 SDK 路径（这台机器上有个坑）
--------------------------------
这个工程用的 SDK 是组件齐全的那一份：

  C:/Users/PIAN/AppData/Local/Android/Sdk

里面补了 platforms/android-35、build-tools/35.0.0、platform-tools、emulator。

而你原来 Android Studio 认的是 D:\Program Files\Android\android-sdk，
那个目录里只有一个空壳 android-35，缺 build-tools，直接构建会失败。

工程根目录的 local.properties 已经指定了正确的 sdk.dir，
所以在本工程里不影响构建。如果想让 Studio 全局也指向新的，
去 Settings > Languages & Frameworks > Android SDK 改一下 SDK Location。


这个 App 是怎么工作的
--------------------
界面还是一份内嵌网页（app/src/main/assets/index.html，约 187 KB），
原生负责三件事：

1. 假装页面来自 https://appassets.local/
   然后用 shouldInterceptRequest 把请求全拦下来。
   好处是页面有正常的 https origin，localStorage 能存住凭证；
   而且页面里 fetch('/api/proxy?...') 是同源请求，不会被浏览器拦。

2. 主文档请求 → 返回 assets 里的 HTML；
   取数请求 → JwxtClient 用 HttpURLConnection 去教务站拿，回来后交还给页面。

3. 教务站证书链缺中间证书，系统默认校验会失败，
   所以对 jwxt.ecjtu.edu.cn/weixin/ 这一个域名放宽了证书校验。
   JwxtClient 里有域名白名单，不会变成任意请求通道。

2.0 新增的第二座桥：window.AndroidTool（ToolBridge.java）
  · state()            通知/精确闹钟/小组件状态
  · requestNotif()     申请通知权限（Android 13+）
  · openNotifSettings() / openExactSettings()
  · schedule(json)     批量排提醒，返回实际条数
  · cancelAll()        撤销全部
  · pushWidget(json)   今日课程推给桌面小组件
  · pinWidget()        请求把小组件钉到桌面
  · exportIcs(name, content)  写文件 + 交给系统日历

  这些方法在 JavaBridge 线程被调用，碰 UI 的都 runOnUiThread，
  返回值统一是 JSON 字符串，网页侧 lib/native.js 负责解析。


改代码从哪下手
--------------
· 改界面、加功能 → 直接改 assets/index.html。
  网页版工程（public/src 下 11 个 ES 模块）还没同步 1.1~2.0 的改动，
  下次重新生成单文件时记得把这些搬回去，否则会被覆盖。

工程配置
--------
包名 com.huajiao.calendar  ·  minSdk 24（Android 7.0）  ·  targetSdk 35
compileSdk 35  ·  Gradle 8.13 + AGP 8.7.3 + JDK 17  ·  versionCode 6 / 2.0

权限：
  INTERNET / ACCESS_NETWORK_STATE          取课表
  POST_NOTIFICATIONS                       上课提醒（Android 13+ 运行时申请）
  SCHEDULE_EXACT_ALARM                     准点响（Android 12+，不给就降级）
  RECEIVE_BOOT_COMPLETED                   重启后恢复闹钟
  VIBRATE                                  通知震动

组件：
  MainActivity            唯一界面，WebView + 两座 JS 桥
  TodayWidgetProvider     桌面小组件
  ReminderReceiver        闹钟到点发通知
  BootReceiver            开机 / 覆盖安装后重排提醒
  IcsProvider             content:// 把导出的 .ics 授权给系统日历

零第三方依赖（WebView 是系统组件，网络用 HttpURLConnection，
ContentProvider 自己实现，不用 androidx 的 FileProvider）。

  · 导出的 .ics 逐项校验：结构完整、88 条 VEVENT（16 周 × 各时段）、
    含 TRIGGER:-PT15M 的 VALARM、首周（8/31 仍在夏季）08:00 正确、
    冬季周次按改过的 08:10 输出、每行 UTF-8 字节数全部 ≤ 75（中文折行没破）
没验证的：
  · 没有在真机上跑过。原生那部分（闹钟准点、通知弹出、小组件渲染、
    系统日历导入）只有代码层面的保证。
  · 提醒的准点率取决于系统的电池策略和精确闹钟授权，这个只能装上试。
  · 考试扫描依赖教务对任意 date 参数都返回当天课表。1.0 起就是这么取数的，
    但一次扫 100 多天属于新用法，如果教务限流，表现是部分天失败——
    缓存里已有数据的那几天仍会显示，不会整页空白。

已知限制
--------
· debug 签名：能装到任何手机，但不能上架应用市场。给同学用可以直接发 apk。
· 教务接口是学校微信端的，随时可能变。变了要改的是网页版的 parser。
· 周视图 7 列挤在 390px 宽里，课程名长的时候会折成两三行，
  地点会被省略号截断（详情看日视图），这是列宽决定的，不是 bug。
· 提醒最多提前排 14 天，打开 App 会自动续排；两周没开过 App 就不会提醒。
· 导出的 .ics 是「一次性快照」，课表变了要重新导，并先删掉旧的那批日程。
